## 0. 一句话需求复述

**让用户从任何地方（主要是 Songsterr 网页框选复制）粘贴来的六线谱文本，都能被尽可能正确地解析成 Fretly 谱面**——小节切分正确、音符时间正确、标题正确、片段不丢。

---

## 1. 问题陈述

目标用户是吉他初学者。他们在 Songsterr 上看到想练的谱，**没有会员无法下载文件**，实际做法是：在网页上框选复制六线谱文本 → 粘贴到 Fretly 的 ASCII 导入框。用户明确表示「ASCII 保持纯粘贴就够了」「我只本地使用，没有版权风险」。

因此 **「粘贴进来的文本能否被正确解析」直接决定了这条核心路径的成败**。当前 `src/io/importers.ts` 的 `parseAscii()` 经实证探测存在 5 个确证缺陷，用户后果如下：

| # | 缺陷 | 用户可见后果 | 严重度 |
| --- | --- | --- | --- |
| 1 | 小节线 `\|` 被 `replace(/[|\s]/g,'')` 完全丢弃，只按列数机械切小节 | 一小节塞进两个小节的内容（实测 18 个音符挤进 1 小节），**所有音符时间错位、节拍器对不上、循环练习无法定位小节**。`\|` 本是 Songsterr 文本里最可靠的节奏锚点，白白浪费 | **P0** |
| 2 | 标题解析被元数据污染：`Title: Wonderwall` → 标题字面就是 `"Title: Wonderwall"`，`Artist:` 被忽略 | 谱库列表里全是「Title: xxx」这种脏标题，无法辨认；作者信息丢失 | P1 |
| 3 | 只支持恰好 6 行；只有 5 行（缺低音 E 弦）的片段直接返回「未识别到六线谱文本」 | **零导入**。Songsterr 片段复制常缺弦，用户拿到的不是「少几个音」而是「全部失败」，被迫放弃 | P1 |
| 4 | 末音符时值延伸到行宽（`nextCol = width`），无小节右边界与跨弦约束 | 一个闷音被拉长到 1320 ticks（实测 `s:5,f:0,t:600,d:1320`），听感上「拖泥带水」，练习时音值完全不对 | P2 |
| 5 | 段落行 `[Intro]` / `[Verse]` 被静默跳过 | 丢失曲式信息；`Measure.sectionLabel` 字段已存在于类型定义中却恒为空串 | P2 |

**核心判断**：缺陷 1 是「解析出来是错的」，缺陷 3 是「根本解析不出来」。前者更危险——用户不容易察觉时间错位，会练出错误的节奏感。这两个必须修。

## 2. 目标与非目标

### 2.1 产品目标（3 个，正交）

1. **正确性优先**：只要文本里存在小节线，就按小节线切分小节，使音符落在正确的 tick 上——正确的小节结构 > 尽量多的音符。
2. **永不零导入**：任何包含至少 1 行可识别弦号的文本都必须产出结果；宁可给出「部分弦块 + partial 标记」，也不整体失败。
3. **元数据与曲式不丢失**：键值对头部（Title/Artist/Tuning/BPM/Tempo）与段落标记（`[Intro]` 等）被结构化提取，而不是当噪音扔掉。

### 2.2 非目标（明确不做，请架构师不要过度设计）

| 编号 | 非目标 | 理由 |
| --- | --- | --- |
| NG1 | **Songsterr URL 自动抓取** | 违反目标站 ToS；架构上不可接受；用户已明确「纯粘贴就够」。任何「输入 URL 就下载」的能力都在本任务范围外 |
| NG2 | **OMR / 五线谱图像识别** | 输入是文本，不是图片。成本极高、收益与初学者痛点无关 |
| NG3 | **Guitar Pro 二进制（.gp3/.gp4/.gp5）解析** | 沿用 `PRD NG5`，保持 `gpImporter` 占位抛错 |
| NG4 | **和弦名称识别（Am/F/G 等）** | ASCII 六线谱文本通常不含和弦名。若文本里出现独立和弦行，本期仅在**不误判为弦块**的前提下忽略，不产 `ChordEvent` |
| NG5 | **自动推断调号 / 变调夹 / 指法（finger）** | 保持现状默认值即可，不引入猜测 |
| NG6 | **改写 `tabToAscii` 的导出格式** | 见 §6 兼容性约束，导出格式是往返一致性的基准 |
| NG7 | 修改 UI 视觉/交互流程 | 本任务只改解析层能力；若需要新的 partial 提示文案，复用现有 `partialTitle / partialKeep` 机制 |

## 3. 用户故事

以「用户从 Songsterr 复制一段谱子粘进来」为主线索：

- **US-1（主场景）** 作为吉他初学者，我想把 Songsterr 页面上框选复制的六线谱原样粘贴进 Fretly，so that 我能立刻开始跟节拍器练习，而不用逐小节手抄。
- **US-2（小节正确性）** 作为正在学节奏的初学者，我想让解析后的小节边界和 Songsterr 上看到的一致，so that 我按 1-2-3-4 数拍时，谱面和节拍器是同步的。
- **US-3（片段容错）** 作为只想要副歌那 8 小节的用户，我想只复制一段（可能只有 4~5 行弦、缺低音 E 弦）也能成功导入，so that 我不用为了凑齐 6 行去手工补全。
- **US-4（元数据）** 作为要管理多份谱子的用户，我想导入后标题就是歌名、作者就是歌手，so that 我在谱库列表里一眼能认出是哪首歌。
- **US-5（曲式）** 作为练习一整首歌的用户，我想看到 `[Intro]` / `[Chorus]` 这些段落名出现在对应小节上，so that 我能直接跳到我卡住的那一段反复练。

## 4. 需求清单（带优先级，每条可验收）

> 说明：本节定义「要什么」与验收口径，不涉及实现方案。代码中的可调参数（列宽、容差）由架构师定，但**语义**必须满足下列验收条件。

### 4.1 P0 · 必须

**R1 — 小节线驱动的切分（缺陷 1）**

- 当文本行的弦内容中存在 `|` 时，`|` 是**小节边界的权威来源**：两个相邻 `|` 之间（或行首/行尾与 `|` 之间）的内容构成一个小节段。
- 行首的 `|`（如 `e|--0--|`）**不**产生空小节；行尾的收口 `|` 同理。
- 每个小节段独立做「列 → startTick」换算，`startTick` 相对于**该小节**起点，取值为 `列偏移 × ASCII_COL_TICKS`（沿用 120 ticks/列，1 列 = 1/16 音符）。
- 6 行弦的**同一行内小节数应一致**；若不一致（如某弦行少写了一个 `|`），以该块内**出现次数最多的段数**为准，多出的段按多余小节追加，少的段视为该弦在这些小节无音符。
- 验收：见 §5 样例 A —— 输入每行 2 个小节，必须解析出 **2** 个小节，且第 2 小节的音符 `startTick` 从 0 重新起算。

**R2 — 无小节线时的列数兜底（缺陷 1 退化路径）**

- 当弦内容中**完全不含 `|`** 时，才回退到现有「按 `asciiColsPerMeasure(ts)` 列数机械切分」的行为。
- 该退化路径必须保持现有测试的语义（见 §6）。

**R3 — 小节线内列数与拍号不匹配时的处理（关键歧义，产品决策见下）**

**产品决策：优先信任小节线，列数仅用于映射时间位置；落在小节容量之外的音符裁剪到小节右边界并标记 partial。**

理由：
1. `|` 是作者在谱面上**显式写下的、信息量最高的**结构声明；列数只是我们为了把文本映射到 tick 的**内部约定**（1 列 = 120 ticks）。当两者冲突时，冲突方几乎是「我们自己的约定」，而不是用户的数据。
2. 初学者最怕的是「小节数不对、循环练习定位不到」；宁可一个小节里音符挤一点，也不能把小节切错或整体报错。
3. 若信任列数，一个 `|` 内写 18 列（用户从 Songsterr 复制的实际宽度）就会被腰斩成 2 个小节，把原本清晰的边界搞乱——即当前缺陷 1 的错误形态。
4. 溢出音符**不丢弃**：保留但把 `startTick` 与 `durationTick` 裁剪到小节容量内（`per = measureTicks(ts)`），并把结果标记为 `partial`，让 UI 继续走「保留已解析部分并导入」的既有流程。这符合 R2「永不零导入」的目标。

- 验收：见 §5 样例 B —— 小节线内列数 ≠ 16（4/4）时，**小节数仍等于 `|` 切出的段数**，且 `partial === true`。

**R4 — 部分弦块可导入（缺陷 3）**

- 允许一个块包含 **1~6 行**。识别规则：块内各行首弦号必须**互异**且**按高音→低音（1→6）或字符串序递增**出现；行数 ≥ 1 即构成一个块。
- 块内缺失的弦**不生成任何音符**，但**不影响其他弦**的解析，也不导致该块被丢弃。
- 只有**完全找不到任何**可识别弦号行时，才返回 `reason: '未识别到六线谱文本'`（保持现有文案与测试）。
- 5 行（e/B/G/D/A）、4 行、甚至 1 行片段都必须能导入。
- 验收：见 §5 样例 C —— 5 行输入必须 `measures.length >= 1` 且音符弦号为 {1,2,3,4,5}。

**R5 — 多块与块间边界（保持并强化）**

- 文本中可存在多个 6 行块（如 `tabToAscii` 每 4 小节输出一个块，块间空行分隔）；R4 允许部分弦块后，块边界识别必须**不把相邻两块的弦行合并**成一块。
- 块与块之间的小节序号、`startTick` 必须连续累加（后一块接续前一块的 `measures.length`），全局 `startTick` 不重置。
- 验收：`tabToAscii(16 小节)` → `parseAscii` 必须得到 16 个小节（§6 已有断言，不得回归）。

### 4.2 P1 · 应当

**R6 — 键值对元数据提取（缺陷 2）**

- 在第一个弦块之前，按行扫描，识别形如 `Key: Value` 的头部（大小写不敏感、允许 `Key：Value` 全角冒号、`Key = Value`）：
  - `Title` / `Song` / `Song Title` → `Tab.title`
  - `Artist` / `Band` / `By` → `Tab.artist`（当前 `asciiToTab` 硬编码为 `'未知'`，需改为使用解析结果，无则保持 `'未知'`）
  - `Tuning` → 解析为 `Tab.tuning`（如 `E A D G B E`、`Drop D`、`D A D G B E`；无法可靠解析时**保持默认**并标记 partial）
  - `BPM` / `Tempo` → `Tab.bpm`（数值须 `clamp` 到 `[MIN_BPM, MAX_BPM]`，非法值忽略）
- 未被识别的键值对行（如 `Album:`、`Copyright:`）**静默忽略**，不计入 partial，也不影响标题。
- **标题回退链**：`Title:` 值 → 第一个弦块之前的首个非空、非元数据、非段落标记行 → `'导入的六线谱'`。
- 验收：见 §5 样例 D —— `Title: Wonderwall` → `title === 'Wonderwall'`（不含 `Title:` 前缀），`artist === 'Oasis'`。

**R7 — 段落标记写入 `sectionLabel`（缺陷 5）**

- 识别独立成行的段落标记：`[Intro]`、`[Verse]`、`[Chorus]`、`[Bridge]`、`[Solo]`、`[Outro]` 以及任意 `[...]` 形式（含中文如 `[前奏]`）。
- 该标记作用于**其后最近的弦块（及其后所有小节，直到出现新的段落标记）**：即从该标记之后第一个弦块的首个小节起，把段落名（去掉方括号）写入 `Measure.sectionLabel`，直到下一个标记生效。
- 若段落标记出现在文本最开头（第一个弦块之前），它同样生效于紧随的弦块。
- 无段落标记时 `sectionLabel` 保持 `''`（不回归现有默认行为）。
- 验收：见 §5 样例 E —— `[Intro]` 后的小节 `sectionLabel === 'Intro'`，`[Verse]` 后的变 `'Verse'`。

### 4.3 P2 · 可以做

**R8 — 音符时值收束（缺陷 4）**

- 同弦音符时值 = `min(下一个同弦音符列 − 当前列, 本小节右边界 − 当前列, 下一个任意弦事件列 − 当前列)`（三者取最小，再按 `ASCII_COL_TICKS` 换算为 tick）。
- 下限 `MIN_NOTE_TICKS`（60）、上限 `per`（小节容量）保持现有约束。
- `'x'`（闷音）音符的时值应受同样规则约束，不得长于到下一事件的距离。
- 验收：见 §5 样例 F —— 末位闷音 `durationTick` 明显小于行宽对应值，且不超过其所在小节剩余容量。

**R9 — `partial` / `failedAt` 语义一致**

- `partial = true` 的触发条件（满足任一）：存在未识别字符（按 `-` 处理，**现有测试语义不得变**）、小节内列数溢出拍号容量（R3）、Tuning 键值对无法解析。
- `failedAt` 继续表示「首个出问题的小节序号（0 起）」，供 UI 提示定位。
- `asciiToTab` 的 `reason` 文案在 `partial === true` 时保持非空（沿用「部分字符未识别，已按延音处理」或架构师定的等价文案，但必须是非空字符串）。

## 5. 验收标准（具体输入 → 期望输出）

> 下列样例均为可写入测试的确定性输入。`t` 表示全局/小节内 `startTick`，`d` 表示 `durationTick`。默认 `ts = [4,4]`，`per = 1920`，`ASCII_COL_TICKS = 120`，`ASCII_DEFAULT_BPM = 90`。

### 样例 A — 小节线驱动切分（R1，P0）

输入（6 行 × 2 小节）：

```
e|--0---0-|--2---2-|
B|--0---0-|--3---3-|
G|--1---1-|--2---2-|
D|--2---2-|--0---0-|
A|--2---2-|--------|
E|--0---0-|--------|
```

期望：
- `measures.length === 2`（**不是 1**）
- 第 0 小节音符数 = 6 行 × 2 = 12（e/B/G/D/A/E 各 2 个）；`startTick` 集合为 `{240, 1200}`（列 2 与列 10 → 2×120、10×120）
- 第 1 小节：A/E 弦无音符；e/B/G/D 各 2 个，`startTick` 集合为 `{0, 960}`（列 0 与列 8，相对本小节起点）
- 所有音符 `startTick < 1920`

### 样例 B — 列数溢出拍号容量（R3，P0）

输入（单小节但内含 18 列内容）：

```
e|--0---0---0---0---|
B|--0---0---0---0---|
G|--1---1---1---1---|
D|--2---2---2---2---|
A|--2---2---2---2---|
E|--0---0---0---0---|
```

期望：
- `measures.length === 1`（**信任小节线**，不切成 2 小节）
- `partial === true`，`failedAt === 0`
- 第 0 小节内所有音符 `startTick + durationTick ≤ 1920`（溢出被裁剪到小节容量内，音符不丢弃）
- 音符数 > 0

### 样例 C — 5 行部分弦块（R4，P0）

输入（缺最低的 E 弦）：

```
Title: Wish You Were Here
Artist: Pink Floyd

e|--0---0-|
B|--1---1-|
G|--0---0-|
D|--2---2-|
A|--3---3-|
```

期望：
- `ok === true` 且 `measures.length >= 1`
- 出现过的弦号集合 ⊆ `{1,2,3,4,5}`，且实际等于 `{1,2,3,4,5}`
- **不返回** `reason === '未识别到六线谱文本'`
- `title === 'Wish You Were Here'`（同时验证 R6）

### 样例 D — 元数据提取（R6，P1）

输入：

```
Title: Wonderwall
Artist: Oasis
Tuning: E A D G B E
BPM: 87
Album: (What's the Story) Morning Glory?

[Intro]
e|--0---0-|
B|--3---3-|
...
```

期望：
- `title === 'Wonderwall'`（不含 `Title: ` 前缀）
- `artist === 'Oasis'`
- `bpm === 87`
- `Album:` 行被忽略，不计入 partial
- 标题不再是纯首行字面

### 样例 E — 段落标记（R7，P1）

输入：

```
[Intro]
e|--0---0-|
B|--1---1-|
G|--0---0-|
D|--2---2-|
A|--3---3-|
E|--------|

[Verse]
e|--3---3-|
B|--0---0-|
G|--0---0-|
D|--0---0-|
A|--2---2-|
E|--3---3-|
```

期望：
- `measures.length === 2`
- `measures[0].sectionLabel === 'Intro'`
- `measures[1].sectionLabel === 'Verse'`

### 样例 F — 末音符时值收束（R8，P2）

输入：

```
e|--------|
B|--------|
G|--s-----|   ← 或等价的 'x' 闷音在 5 弦
D|--------|
A|--5-----|
E|--------|
```

期望：
- 该闷音 `durationTick` 满足：`durationTick ≤ (本小节右边界 − startTick)` 且 `durationTick < 行宽对应 tick`（即不再出现「未受约束地拉到行尾」）
- `durationTick >= MIN_NOTE_TICKS`（60）

### 样例 G — 非谱面文本仍被拒绝（回归，全部优先级）

输入：`这是一段普通文字，没有六线谱。`
期望：`ok === false`，`reason === '未识别到六线谱文本'`（文案不变）

### 样例 H — 往返一致（回归，全部优先级）

`tabToAscii(tab)` → `asciiImporter.parse()`：小节数一致（16）、`signature`（`index:string:fret` 集合）一致。

## 6. 兼容性约束（硬性，架构师必须守住）

以下为**不可破坏的既有契约**，新能力必须是**增量**的：

1. **`src/io/__tests__/io.test.ts` 中 5 条 ASCII 相关断言不得修改**：
   - `'导出 → 导入后小节数与 (弦, 品) 集合一致'` —— 16 小节 + signature 相等。
   - `'ASCII 导出每 4 小节一行，行首为 e/B/G/D/A/E'` —— 导出格式不变。
   - `'未识别字符按 \`-\` 处理并计入部分解析（PRD Q5）'` —— `@` 仍按 `-` 处理、`partial === true`、`title === '测试曲'`（该样例无元数据前缀，标题回退链必须仍取到它）。
   - `'识别数字弦号开头的块，且不要求小节线对齐'` —— `1|---0-- … 6|0-----` 仍解析为 **1** 个小节，弦号 `[1..6]`。注意此样例**含 `|`**（行首），R1 要求行首 `|` 不产生空小节，故仍为 1 个小节。
   - `'完全不是六线谱时给出明确原因'` —— 原因文案 `'未识别到六线谱文本'` 不变。
2. **`tabToAscii` 往返一致**：本项目自己导出的 ASCII 再导入必须仍等价（16 小节 / signature 相等）。导出格式 `e|....|....|`、每行 4 小节、行尾收口 `|` 不变。
3. **`asciiColsPerMeasure` / `ASCII_COL_TICKS` / `ASCII_DEFAULT_BPM` 三个导出的常量语义不变**（`exporters.ts` 依赖它们）。
4. **`parseAscii` 的函数签名保持 `(text, ts?) => ParsedAscii`**；`ParsedAscii` 可**新增可选字段**（如 `artist`、`tuning`、`bpm`），但**不得删除或改型**现有字段 `title / measures / partial / failedAt / reason`。
5. **`asciiImporter` 的 `id/label/accept/fromText` 与 `ImportResult` 契约不变**；`source.importer === 'ascii'`、`source.type === 'imported'` 不变。
6. **`Measure.sectionLabel` 复用现有字段**，不新增类型；不改动 `src/types/tab.ts` 的既有字段语义。
7. 新增行为（R1/R3/R4/R6/R7/R8）只能**叠加**在上述契约之上；若某新规则与既有断言冲突，**以既有断言为准**并回报团队。

## 7. 风险与取舍

| # | 风险 | 说明 | 应对 / 取舍 |
| --- | --- | --- | --- |
| RISK-1 | **宽松解析把非谱面文本误判为谱面** | R4 允许 1~6 行后，「`E` 单行 + 一些数字」可能被当成谱。例如一段以 `A:` 开头的正文会被误认为 A 弦行 | **边界**：块内必须至少 1 行**弦号后紧跟终止符**（`\|` 或空白）后接内容；且内容中必须出现**至少一个音符字符（0-9 或 x/X）**，纯 `---` 不算。单行块额外要求该行以 `\|` 收口或含 `\|`。这能挡住「普通句子」，同时保住「一行片段」 |
| RISK-2 | **信任小节线导致音符挤压 / 重叠** | R3 下一个小节可能塞进超过拍号容量的列，出现同 tick 挤音 | 接受「挤」，但**不裁剪丢弃**、**不改变小节数**；标记 `partial` 让用户知情。取舍：结构正确 > 时间精确 |
| RISK-3 | **跨行小节数不一致**（某弦漏写 `\|`） | 6 行粘贴时个别行可能断行 | 取众数（R1）；差异行按「多退少补」处理，同时置 `partial = true`，不整体失败 |
| RISK-4 | **元数据误提取** | 歌词行如 `Verse: blah` 可能被当成键值对 | 只识别白名单键（Title/Song/Artist/Band/By/Tuning/BPM/Tempo）；其他 `Key: Value` 忽略。标题回退链保证即使全部忽略也能取到合理标题 |
| RISK-5 | **段落标记位置模糊** | `[Chorus]` 写在两个弦块之间 vs 紧贴块内 | 决策：标记「作用于其后最近的弦块起，直到下一个标记」。写在块前或块后效果等价于「下一个块起」 |
| RISK-6 | **两位数品位宽度歧义** | `--12--` 是「1 品 2 品」还是「12 品」 | 沿用现有规则：连续数字最多 2 位，合成一个品位（`12` → 12 品）。这是既有行为，不改 |
| RISK-7 | **回归风险**：改动切分逻辑可能打破 16 小节往返 | R1 改为小节线驱动后，`tabToAscii` 输出的 `\|` 恰好使切分更准 | 强制要求：先跑通 §6 全部 5 条断言 + 样例 H 才可合入 |

**总体权衡原则**：*宁可给用户一个「标注了 partial 的、结构正确的结果」，也不要给一个「静默错误的结果」或「零结果」。* 正确的小节结构是第一优先级；时间精度的瑕疵通过 `partial` 显式暴露，让用户自行决定是否使用。
