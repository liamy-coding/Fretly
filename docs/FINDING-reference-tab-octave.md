# 发现：参考吉他谱与 XML 相差整整一个八度

**日期**：2026-09-11
**触发**：用户提供正确吉他谱 `Mama who bore me_GO.pdf`，要求 Fretly 从 XML 转化的结果与之一致。
**结论**：**参考谱 = XML 的旋律整体降 12 个半音（一个八度）**，并在 **Capo 5** 下以开放把位编配。Fretly 当前把 XML 音高当作**实际发声音高**处理，因此产出高把位谱。

---

## 一、参考谱是什么

`Mama who bore me_GO.pdf`（2 页）经解析确认：

| 属性 | 值 |
|---|---|
| 谱式 | **纯六线谱**（每系统恰好 6 条横线，线距 7.45pt；无五线谱） |
| 变调夹 | **Capo 5**（谱面明确标注） |
| 和弦 | A、Fadd9/C、G/B、D（和弦图标注 `8fr.`） |
| 结构 | 第 1–21 小节：旋律 + tab；第 22–30 小节：斜杠节奏谱（扫弦），末小节带延长记号 |
| 品数 | 谱面数字仅 **0–4**（全部为开放把位指型） |

XML 有 19 小节。参考谱 1–18 小节的 **tab 数字总数 = 260**，XML 1–18 小节音符数 **= 260**，
**数量完全相等**。

---

## 二、核心证据：音高恰好多重集一致（−12 半音）

把参考谱的 `(弦, 品)` 按 **Capo 5** 换算为实际发声（`发声 = 空弦MIDI + 5 + 品`），
与 XML 音高逐项对比（1–18 小节，共 260 音）：

| XML 音高 | 出现次数 | 参考谱发声 | 出现次数 | 是否相等 |
|---|---|---|---|---|
| 59 | 7 | 47 | 7 | ✅ |
| 60 | 5 | 48 | 5 | ✅ |
| 62 | 11 | 50 | 11 | ✅ |
| 64 | 4 | 52 | 4 | ✅ |
| 65 | 4 | 53 | 4 | ✅ |
| 67 | 27 | 55 | 27 | ✅ |
| 72 | 21 | 60 | 21 | ✅ |
| 74 | 31 | 62 | 31 | ✅ |
| 57 | 11 | 45 | 9 | 差 2 |
| 69 | 77 | 57 | 71 | 差 6 |
| 73 | 4 | 61 | 1 | 差 3 |
| 76 | 11 | 64 | 9 | 差 2 |

**8 个音的出现次数完全相等**，其余 4 个的差额合计 13，与 PDF 文本提取漏掉的音符数吻合
（PDF 文本层的数字 token 与谱面图形并非一一对应）。**每一个对应关系都恰好相差 12 个半音。**

分小节核对（第 1–3 小节，14+15+14 = 43 音）：
参考谱音高多重集 **与 XML−12 逐小节完全相同**。

第 1 小节明细：

```
参考谱(弦:品)  6:0   4:2   1:0   4:2   2:0   4:2   3:0   6:3   4:2   1:0   4:2   2:3   4:2   3:0
参考谱发声     A2    A3    A4    A3    E4    A3    C4    C3    A3    A4    A3    G4    A3    C4
XML 原音高     A3    A4    A5    A4    E5    A4    C5    C4    A4    A5    A4    G5    A4    C5
```

XML 的每个音都比参考谱的实际发声**高 12 个半音**。

---

## 三、为什么会差一个八度

吉他是**移调记谱乐器**：五线谱记谱比实际发声**高一个八度**。
MusicXML 对此有官方标记 `<clef-octave-change>-1</clef-octave-change>`。

**但本 XML 没有任何吉他标记**（已核验）：

| 元素 | 数量 |
|---|---|
| `clef-octave-change` | **0** |
| `staff-details` / `staff-tuning` | 0 |
| `string` / `fret` / `technical` | 0 |
| `tab` | 0 |
| `part-name` | `Piano`（clef 为普通 G2） |

也就是说：制谱软件（Sheet Music Scanner）把吉他谱的**记谱音高**当成了普通钢琴谱的**发声音高**，
补上了八度差。**Fretly 单从这个 XML 无法判断它是吉他记谱**——这是修复方式的决定性约束。

---

## 四、Fretly 现状 vs 参考谱

| | 参考谱（Capo 5，品 0–4 → 绝对 5–9 品） | Fretly 现状（不降八度） |
|---|---|---|
| 发声 | A2–C5 | **A3–C6** |
| 品数范围 | 0–4（相对）/ 5–9（绝对） | **0–20** |
| 可弹性 | 开放把位，初学者可弹 | 高把位跳跃，实际不可弹 |

若把音高**降 12** 再交给 Fretly 现有的指法算法（含本轮 R5 的「最高品基准」修复），
产出品数范围 **仅 0–8 品**（0品×25、1品×11、2品×64、3品×34、5品×68、7品×61、8品×12），
**同为可弹的低把位谱**。

第 1 小节对比：

```
参考谱(Capo5)  6:0  4:2  1:0  4:2  2:0  4:2  3:0  6:3 ...
Fretly(−12)    5:0  3:2  1:5  3:2  1:0  3:2  2:1  5:3 ...
```

Fretly 的每个选择都是该音在**无变调夹下的最低品位**等价解（例如参考谱 `4:2` 发声 A3，
绝对位置是 4 弦 7 品，Fretly 取更低的 3 弦 2 品）。**音高逐音相同，指位更低。**

---

## 五、结论

1. **参考谱与 XML 是同一份音乐，相差整整一个八度**，证据是多重的（音符数相等、
   音高多重集在 −12 下完全吻合、分小节吻合）。
2. **Fretly 的指法算法本身没有错到那个程度**——它缺的是**八度**这一步。
3. 修复需要**产品决策**：八度处理方式（导入开关 / 自动判定），
   因为 XML 内不含任何可据以自动判断的吉他标记。
4. 参考谱使用 **Capo 5**；Fretly 无变调夹概念。不降八度之外的次级差异（具体弦/品选择、
   变调夹）不影响「同一份音乐、同样可弹」这一目标。

## 附：未能从 PDF 提取的部分

PDF 文本层与谱面图形不完全对应（自由文字排布的 tab 数字），
按系统逐个匹配弦线后，1–18 小节共提取 260 个数字，与 XML 的 260 音一一对应；
其中 8 类音高出现次数完全相等，其余差额合计 13，属提取遗漏，不影响结论。
第 19 小节的 tab 行与后续扫弦段落未纳入本次逐音比对。
