## 0. 已裁决的硬约束（写入 PRD，不再讨论）

| # | 决策项 | 裁决结果 | 对一期的直接影响 |
|---|---|---|---|
| 1 | 扒谱推理方式 | **不做云端 GPU**。定义 `TranscriptionProvider` 抽象接口；先实现**浏览器端本地启发式 Provider**（Web Worker 内：音频解码 → 能量 onset 检测 → YIN-lite 自相关音高估计 → chroma 和弦模板匹配 → 简易节拍/小节估计 → 指板 DP 映射 → 输出带 confidence 的 Fretly JSON）。同时保留 `RemoteProvider` 空壳（`POST /api/transcribe`，不启用） | 扒谱**不限次、零成本、无需队列**；UI 必须诚实标注"本地轻量引擎" |
| 2 | Guitar Pro 解析 | **不自研二进制解析**。MVP 支持导入 Fretly JSON / MusicXML / ASCII 六线谱文本；GP 列 P1，代码预留导入器接口 | A 模块导入从 4 种降为 3 种；GP 相关 UI 不出现 |
| 3 | 账号体系 | **免登录本地优先**。数据存 localStorage（索引/设置）+ IndexedDB（谱面/音频/草稿），不引入任何后端账号 | 无登录页、无用户表；所有数据带 `localOnly: true` 语义 |
| 4 | 额度 | 本地推理**不限次** | 产品文案中**禁止出现**"今日额度 / 剩余次数 / 免费 N 次"等字样 |
| 5 | 移动端 | 只做**响应式 Web**（桌面优先，≥768px 可用） | 不做 PWA 安装、不做 App、不做 manifest install 提示 |
| 6 | 示范音轨 | **Web Audio 合成吉他音色**（推荐 Karplus-Strong 拨弦物理建模，零采样体积），**必须支持变速不变调** | 不引入 SoundFont 文件；合成器是 P0 基础设施 |

**版权红线（贯穿全文，任何实现不得违反）**

1. 内置示范曲**必须原创命名 + 原创或公有领域旋律**。禁止使用任何受版权保护的流行歌曲曲名、旋律、和弦进行编配。
2. 官方不预置任何商业曲库；扒谱功能定位为"对用户自有或已获授权音频的辅助转录"，上传前需勾选权属声明。
3. 不提供任何音视频平台的下载/破解能力（PRD v1.0 的 C10 在线链接解析本期不做）。

## 1. 一期目标与非目标

### 1.1 一期目标（M1 完成时可对外演示的完整闭环）

> **一句话**：用户打开网页 → 5 分钟内拿到一份能弹的谱 → 用渐进加速练会它 → 看见自己的熟练度在涨。

| # | 目标 | 可判定结果 |
|---|---|---|
| G1 | **谱库能装东西且找得到** | 内置 4 首原创示范曲 + 支持 3 种格式导入 + 调/难度/BPM/来源四维筛选 + 曲名模糊搜索 + 歌单；导出 JSON / PDF（打印）/ ASCII |
| G2 | **练习器真的能练** | 六线谱 Canvas 渲染 + 同步播放头 + 0.5x–1.5x 无级变速（保音高）+ A-B 循环 + 节拍器 + 合成示范音轨 + **渐进加速训练（★核心）** + 和弦指位图 + 难点标记 + 视图切换 |
| G3 | **扒谱能产出可校对的初稿** | 上传本地音频（≤50MB）或麦克风录制 → 本地 Worker 推理 → 输出「和弦进行 + 旋律骨架 + 节拍/小节」+ 逐音符 confidence |
| G4 | **校对 3 分钟能收尾** | 波形时间轴 + 六线谱编辑 + 和弦轨 + **待确认清单（★核心，进度条式）** + 节奏型模板库（12 个）+ 一键入库 |
| G5 | **档案能看见进步** | 练习计时 + 打卡日历 + 曲目熟练度（0–100）+ 速度曲线 + 错题本（基于难点标记） |

### 1.2 非目标（本期**明确不做**，任何人不得私自扩大范围）

| # | 不做的事 | 原因 |
|---|---|---|
| NG1 | 麦克风跟弹实时评分（PRD v1.0 的 D1–D4） | 依赖拾音设备，误判风险高，留到 M3 |
| NG2 | 云同步 / 多设备同步 | 决策 3：免登录本地优先，无后端 |
| NG3 | 社区分享、协作校订、评分 | 无账号、无后端，且内容合规风险高 |
| NG4 | 付费 / 订阅 / 任何商业化入口 | 同上 |
| NG5 | Guitar Pro 二进制解析（.gp3/.gp4/.gp5） | 决策 2：只预留导入器接口 |
| NG6 | PDF / 图片 OCR 导入 | 需服务端视觉模型 |
| NG7 | 谱面版本管理与 diff（PRD v1.0 的 A7） | 无后端；本期谱面用 `revision` 自增计数，不做历史快照 |
| NG8 | 在线音频直链解析（PRD v1.0 的 C10） | 合规要求 |
| NG9 | 云端扒谱任务队列、站内通知 | 决策 1：本地推理，秒级/十秒级完成，无需异步队列 |

| NG12 | 用户注册/登录/找回密码 | 决策 3 |

## 2. 用户故事

> 格式：作为…我想…以便…
> 每条附**验收要点**（可判定），覆盖 A / B / C / C5 / E 五个模块。

### A · 谱库 Archive

**US-01 作为初学者，我想一打开就看到内置示范曲，以便不用先找谱就能开始练。**
- 验收要点：首次访问（localStorage 无 `fretly.seeded`）时自动播种 4 首原创示范曲；曲库列表首屏出现 4 张卡片，卡片显示曲名、调、BPM、难度星级、熟练度 0%；播种后写入 `fretly.seeded=true`，刷新不重复播种。

**US-02 作为有存量谱子的用户，我想导入 MusicXML / ASCII 谱 / Fretly JSON，以便把散落的谱子收进一个地方。**
- 验收要点：导入入口支持"选择文件"与"粘贴文本"两种；JSON 与 MusicXML 走文件，ASCII 走粘贴；导入成功后列表 +1 并 toast「已导入《X》」；导入失败时弹窗显示"已解析 N 小节，第 M 小节解析失败"并提供「保留可解析部分继续导入」按钮。

**US-03 作为练习者，我想按调、难度、BPM、来源筛选并用曲名搜索，以便 3 秒找到今天要练的那首。**
- 验收要点：筛选器四个维度可叠加；默认排序为「最近练习」（无练习记录时按 `updatedAt` 倒序排在最后）；搜索框输入 2 字符起实时过滤（防抖 200ms）；筛选后无结果显示空状态「没有符合条件的谱子 · 清除筛选」。

**US-04 作为整理控，我想自建歌单（如"本周攻克"），以便把要练的曲子归到一起。**
- 验收要点：左栏可新建歌单，输入名称回车即创建；曲目卡片 hover 出现「加入歌单」；歌单内曲目可移除（不删除原曲）；删除歌单需二次确认且不删除曲目本身。

**US-05 作为要带谱出门的人，我想导出 PDF / ASCII / JSON，以便打印或分享给琴友。**
- 验收要点：三个导出项各触发一次浏览器行为——PDF 调 `window.print()` 并加载打印样式表（隐藏导航与控制栏，六线谱黑白分页）；ASCII 触发 `.txt` 下载；JSON 触发 `.json` 下载且可被本产品重新导入成功（往返无损）。

### B · 练习器 Practice

**US-06 作为卡在某一小节的人，我想框选 2–4 小节做 A-B 循环，以便反复啃难点而不是从头弹到尾。**
- 验收要点：点击小节头可选 A 点、再点选 B 点，选中区间以蓝色底显示；播放到 B 点自动跳回 A 点；再次点击「清除循环」恢复整曲；循环区间可拖动端点微调（小节粒度）。

**US-07 作为想提速的人，我想把速度降到 60% 且音高不变，以便跟着原调慢练。**
- 验收要点：变速滑块范围 0.50–1.50，步进 0.01，实时显示 `当前 BPM = round(原曲BPM × ratio)`；**用电子调音器或频谱验证：0.5x 与 1.0x 下同一个音符的基频误差 < 10 音分**（即不变调）。

**US-08 作为想科学提速的人，我想一键开启渐进加速训练，以便从 60% 自动爬到原速，不用手动调速。**
- 验收要点：面板常驻谱面下方，含「起始速度（默认 60%）/ 每轮增量（默认 +5 BPM）/ 达标轮次（默认 2 轮）/ 目标速度（默认 100%）」四个参数 + 「开始训练」按钮；连续达标 2 轮后自动提速 **且播放不中断**（播放头不回到 A 点、音频无爆音）；到达目标速度并达标后显示「已达成目标速度 🎉」并记录 `targetReachedAt`；柱状图实时显示每轮 BPM。

**US-09 作为总在换和弦时断拍的人，我想看到当前和弦指位图和"下一个和弦"预告，以便提前准备左手。**
- 验收要点：右栏当前和弦显示指位图（6 弦×5 品网格，含 `x`/`o` 标记与横按弧线）；提前 1 拍显示下一个和弦名与小号指位图；F 大横按（133211）旁显示「简易替代」按钮，点击切换为 `xx3211` 并重渲染。

**US-10 作为练琴时手忙的人，我想给卡住的小节打"难点"标记，以便下次直接定位。**
- 验收要点：点击小节右键菜单 / 或工具栏「标记难点」→ 该小节出现琥珀色虚线框；右栏「难点标记」列表新增一条并可点击跳转；标记可删除；**每个标记自动进入档案页错题本**。

**US-11 作为不想被谱面分心的人，我想切到"纯听模式"，以便练耳朵。**
- 验收要点：视图切换含「六线谱 / 和弦歌词 / 仅和弦 / 纯听」四项；选「纯听」后谱面区域隐藏，控制栏与节拍器保留；切换不中断播放。

**US-12 作为需要节奏参考的人，我想要节拍器和合成示范音轨，以便知道该多快、听起来是什么样。**
- 验收要点：节拍器可开关、可选拍号（4/4、3/4、6/8）、可选 subdivision（1/4、1/8、1/16）、开启预备拍（1 小节 count-in）；示范音轨用 Web Audio 合成，可与节拍器同时发声且音量独立可调；**变速到 0.5x 时示范音轨音高不变**。

### C · 扒谱 Transcribe

**US-13 作为听到一段想弹的吉他的人，我想上传本地音频，以便拿到一份和弦 + 旋律的初稿。**
- 验收要点：拖拽或选择文件，接受 mp3/wav/m4a/flac/ogg，>50MB 时拒绝并提示「文件超过 50MB，请裁剪后再试」；上传前必须勾选「我确认该音频为本人所有或已获授权」；提交后进入推理，页面显示阶段文案与百分比，可「取消」。

**US-14 作为只有一把琴和电脑麦克风的人，我想直接录制一段，以便把我刚弹的 riff 变成谱。**
- 验收要点：点击「录制」请求 `getUserMedia({audio:true})`；录制最长 5 分钟，实时显示计时与输入电平；停止后可回放确认 / 重录 / 用于推理；权限被拒时显示引导文案且其余功能不受影响。

**US-15 作为被 AI 结果误导过的用户，我想知道哪些地方不可信，以便只检查那几处。**
- 验收要点：六线谱上 confidence < 0.45 的音符显示琥珀色虚线框，0.45–0.70 显示浅灰虚线框，≥0.70 无标记；波形时间轴上低置信区段有半透明黄色遮罩；初稿整体平均 confidence < 0.40 时顶部横幅提示「这份音频自动扒谱效果不佳」，并提供「仅用和弦模式」降级按钮。

**US-16 作为不想被忽悠的人，我想知道这是本地轻量引擎，以便对精度有正确预期。**
- 验收要点：扒谱页右栏常驻「效果预期」说明卡 + 引擎标签「本地轻量引擎 · 不限次」；页面任何位置不出现"AI 云端""额度""剩余次数"。

### C5 · 校对编辑器

**US-17 作为不想无限校对的人，我想看到「还有 N 处需要确认」并能逐条跳，以便知道还要多久。**
- 验收要点：编辑器顶部进度条显示 `已确认 X / N`；「跳到下一处 ▸」按钮把播放头与六线谱选区定位到下一处低置信项并高亮；每确认一处（点击「✓ 确认」或编辑该音符）N 减 1，全部确认后进度条变绿并显示「全部确认完毕」。

**US-18 作为不会扒扫弦的人，我想从节奏型模板里挑一个一键铺满，以便 30 秒得到能弹的扫弦谱。**
- 验收要点：模板库含 12 个模板，按「扫弦 / 分解」分组，图形化（条形起伏）+ 试听按钮；选中后预览区显示应用到当前和弦进行后的和弦序列与速度；「应用到全部并生成谱面」一键生成六线谱音符；支持逐小节替换不同模板。

**US-19 作为发现某处扒错了的人，我想点一下就改品位/换弦/换和弦，以便快速修完。**
- 验收要点：点击音符 → 右侧属性面板显示 `弦 / 品 / 时值 / 置信度`，品位数可直接输入 0–24；点击和弦轨上的和弦 → 弹窗列出候选和弦（按 chroma 距离排序），选中即替换并同步重生成该小节音符；悬停低置信音符显示候选位置（如"6弦3品 或 5弦7品"），点击即切换。

**US-20 作为怕丢工作的人，我想编辑器自动保存草稿，以便误关页面不丢。**
- 验收要点：每 30 秒自动保存 + `beforeunload` 保存；重新打开同一 job 时提示「检测到未完成的草稿，是否继续？」；撤销/重做支持 ≥50 步（`Cmd/Ctrl+Z`、`Cmd/Ctrl+Shift+Z`）。

**US-21 作为改完的人，我想一键入库，以便马上开练。**
- 验收要点：「完成并入库」是编辑器唯一出口按钮（右上角，主色）；点击后写入谱库（source.type = `transcribed`，携带 `confidence` 与 `jobId`），跳转 `/practice/:id`，熟练度初始 0。

### E · 档案 Record

**US-22 作为怕自己没坚持的人，我想看到打卡日历和连续天数，以便别断。**
- 验收要点：日历按自然月渲染，有练习的日期填充主色并显示当日分钟数；顶部显示「连续 N 天」（当日或昨日有练习才连续，否则归零）；单次会话有效练习时长 ≥ 5 分钟才计入打卡。

**US-23 作为怀疑自己没进步的人，我想看到熟练度分数和速度曲线，以便确认自己在变快。**
- 验收要点：每首曲目显示熟练度 0–100（带进度条）；档案页速度曲线以「日期 × bestBpm」折线呈现，至少 2 个数据点才画线，否则显示「再练一次就会出现曲线」；熟练度在每次会话结束时重算（见 §6 公式）。

**US-24 作为反复在同一处卡住的人，我想有错题本并能一键生成专项练习，以便针对性攻克。**
- 验收要点：错题本列出所有难点标记，按「被设为循环区次数 + 标记时间」排序，显示曲名 + 小节号 + 备注；「生成专项练习 ▸」跳转练习器并自动把该小节 ±1 小节设为 A-B 循环、速度设为 60%、开启渐进加速。

### 全局 / 合规

**US-25 作为担心隐私的人，我想确认我的数据只在本机，以便放心用。**
- 验收要点：设置页显示「数据存储：本机浏览器（IndexedDB）」+ 明确文案「不上传任何谱面与音频」；提供「导出全部数据（JSON）」与「清空本地数据（二次确认）」；任意页面打开 DevTools → Network，除 CDN 静态资源外无谱面/音频相关请求。

**US-26 作为用平板的人，我想在 ≥768px 屏幕上也能正常用，以便不只在电脑上练。**
- 验收要点：768–1023px 下左栏歌单折叠为抽屉、控制栏换行不重叠、六线谱横向滚动可用；< 768px 时显示提示条「建议使用 ≥768px 宽的屏幕获得完整体验」，但谱面只读浏览仍可用。

## 3. 需求池（M1）

> **优先级定义**
> - **P0**：M1 必做。缺失则闭环断裂，不可交付。
> - **P1**：M1 尽量做；排期紧张时可整体顺延，但不得影响任何 P0 的验收。
> - 表中以「※」标注的子能力为 P1，不单独占编号。
>
> **统计：61 条主需求 —— P0 59 条 / P1 2 条；另有 7 项 P1 子能力以 ※ 标注。**
>
> 每条验收标准必须**可判定**（"点击 X 后出现 Y"）。禁止"优化体验""提升流畅度"类描述。

### A · 谱库 Archive（11 条）

## 4. 关键交互与状态说明（逐页）

> 五页：`/library` 谱库 · `/practice/:id` 练习器 · `/transcribe` 扒谱 · `/transcribe/:jobId/edit` 校对编辑器 · `/dashboard` 档案。

### 4.1 谱库 `/library`

**页面要素**
1. 顶栏：Logo + 5 个导航（谱库 / 扒谱 / 档案 / 设置）+ 右侧「+ 导入 / 扒谱」主 CTA
2. 左栏（≥1024px 常驻，768–1023px 抽屉）：我的歌单列表（含「全部曲目」「最近练习」「内置示范曲」三个系统分组）+「+ 新建歌单」
3. 主区顶部：搜索框 + 视图切换（网格/列表）+ 筛选栏（调 / 难度 / BPM / 来源，收起为「筛选 (n)」按钮）
4. 主区：曲目卡片网格
5. 卡片悬浮菜单：加入歌单 / 导出（JSON·PDF·ASCII）/ 编辑 / 删除

**主要交互**
- 点击卡片 → `/practice/:id`（**直接进入练习器，不是详情页**；详情页从卡片右上角「ⓘ」进入）
- 筛选/搜索为客户端计算，无网络请求；结果数实时更新
- 卡片熟练度进度条点击 → 跳 `/dashboard` 并高亮该曲
- 排序切换下拉：最近练习（默认）/ 最近添加 / 熟练度 / 难度 / BPM

**空状态**
- 首次进入（已播种）：4 张内置示范曲卡片 + 顶部引导条「先从内置练习曲开始，或导入你自己的谱子」
- 曲库为 0 首（用户清空后）：三卡片引导「导入现有谱 / 扒一首新歌 / 试玩内置示范曲」
- 筛选无结果：「没有符合条件的谱子」+「清除筛选」按钮
- 歌单为空：「这个歌单还是空的 · 去谱库添加曲目」+ 跳回全部曲目按钮

**加载态**
- 首屏：卡片骨架屏（6 个灰块，含 shimmer），IndexedDB 读取完成后替换（通常 < 200ms）
- 导入中：按钮转圈 + 进度文案「正在解析…」；> 3s 显示「文件较大，请稍候」

**错误态**
- 导入失败：弹窗显示「已解析 N 小节，第 M 小节解析失败（原因：XXX）」+「保留可解析部分继续导入」/「放弃」
- 文件格式不符：「不是有效的 Fretly 谱面文件」（JSON）；「未找到可导入的吉他轨」（MusicXML）；「未识别到六线谱文本」（ASCII）
- IndexedDB 不可用（隐私模式）：顶部红色横幅「浏览器存储不可用，数据将无法保存。请关闭无痕模式后重试」，功能只读

**边界条件**
- 曲名超长：卡片两行省略号，列表视图单行省略号
- 无艺人：显示「未知」
- 无标签：标签区隐藏，不占位
- 曲目数 > 100：网格虚拟化（只渲染可视区 + 上下各 2 行缓冲）
- 同时打开两个标签页：以最后写入为准，另一标签页在 `storage` 事件时 toast「数据在另一标签页已更新，刷新查看」

### 4.2 练习器 `/practice/:id`

**页面要素**
1. 元数据头：曲名 · 艺人 · 调 · Capo · BPM · 拍号 · 难度星级 · 熟练度徽章（常驻）
2. 视图切换（六线谱 / 和弦歌词 / 仅和弦 / 纯听）
3. 谱面渲染区（Canvas，可横向滚动 + 按小节换行）
4. 控制栏：播放/暂停、上一/下一小节、A-B 循环开关、变速滑块 + 当前 BPM、节拍器开关、示范音轨开关 + 音量、点击音符试听
5. 渐进加速训练面板（★ 常驻谱面下方，不折叠）：四参数 + 开始/暂停 + 柱状图 + 「本轮过了」按钮
6. 右栏：当前和弦指位图 + 预告下一个和弦 + 简易替代 + 难点标记列表 + 本次练习计时

**主要交互**
- 播放 → 蓝色播放头随 tick 前进，当前小节浅蓝底、当前音符加粗
- 点小节 → 选 A；再点 → 选 B；`L` 快捷键开关循环
- 拖变速滑块 → 即时生效不重启；显示 `BPM = round(tab.bpm × ratio)`
- 点「开始训练」→ 按 §6.2 规则从 startBpm 起播；每轮结束显示「本轮过了」，连续达标 2 轮自动提速且**不中断播放**
- 点击音符 → 立即试听（合成音色）
- 标记难点 → 该小节琥珀色虚线框，右栏列表 +1

**空状态**
- 谱面 0 小节：「这份谱子还没有内容 · 去编辑器添加」+ 跳编辑器按钮（仅手动/导入的谱可能出现）
- 无和弦：和弦图区显示「这份谱子没有和弦标记」
- 无难点标记：右栏「还没有难点标记 · 点击小节上的旗子图标添加一个」
- 速度柱状图无数据：显示「开始训练后这里会出现速度曲线」

**加载态**
- 谱面加载：Canvas 区域骨架 + 「正在渲染谱面…」；> 1s 显示小节进度「已渲染 12/48 小节」
- 音频引擎初始化：首次播放需 `AudioContext.resume()`（浏览器自动播放限制），期间播放按钮显示「点击激活音频」

**错误态**
- 谱面数据损坏（schema 校验失败）：整页错误卡「这份谱子数据已损坏」+「返回谱库」+「导出原始数据（供排查）」
- 浏览器不支持 Web Audio：红色横幅「当前浏览器不支持 Web Audio，示范音轨与节拍器不可用」，谱面与播放头仍可用（用 `setTimeout` 驱动 tick）
- 和弦名不在和弦库：指位图区显示「未知和弦 · C?」并在 console 警告，不崩溃

**边界条件**
- 48 小节以上长谱：Canvas 只渲染可视区 ±2 小节，滚动时重绘
- 变速到 0.5x 时 BPM < 40：仍允许，节拍器 subdivision 强制降为 1/4
- A-B 区间 < 1 小节：允许（最小 1 拍 = 480 ticks）
- 到达曲尾：停止并重置播放头到 A 点（有循环）或曲首（无循环）
- 会话计时：暂停 ≥60s 自动结束会话；切换标签页 > 5 分钟自动结束会话
- 熟练度在会话进行中不变，会话结束时更新（见 §6.1）

### 4.3 扒谱上传 `/transcribe`

**页面要素**
1. 大拖拽区：「拖拽音频到这里，或 选择文件」+「🎤 录制」并列
2. 格式说明：「支持 mp3 / wav / m4a / flac / ogg，≤ 50MB」
3. 权属声明勾选框（提交前必填）
4. 处理选项面板：乐器类型（独奏吉他 / 弹唱伴奏）二选一
5. 任务列表：状态（处理中 / 待校对 · N 处 / 已入库）+ 时间 + 文件名 + 操作按钮
6. 右栏「效果预期」卡 + 引擎标签「本地轻量引擎 · 不限次」

**主要交互**
- 拖入/选择文件 → 显示文件名、大小、时长 → 选项面板展开 → 勾选权属 → 「开始扒谱」可点
- 点击「录制」→ 请求麦克风 → 实时电平条 + 计时 → 停止 → 回放/重录/用于推理
- 提交 → Worker 推理 → 进度条（7 阶段 + 百分比）+「取消」
- 推理完成 → 卡片变「待校对 · N 处」+「打开编辑器」按钮（**N 直接写在按钮上**）

**空状态**
- 无任务：「还没有扒谱任务 · 上传一段音频开始」
- 未选文件：处理选项面板禁用（灰态）+ 文案「先选择一个音频文件」

**加载态**
- 推理中：进度条 + 阶段文案（「解码音频」「检测音符起点」「估计音高」「识别和弦」「分析节拍」「映射指板」「生成初稿」）+ 百分比 +「取消」
- 取消后回到上传态并 toast「已取消」

**错误态**
- 文件 > 50MB：「文件超过 50MB，请裁剪后再试」
- 不支持的格式：「暂不支持 .xxx 格式」
- 未勾权属：「请先确认音频权属」（按钮禁用 + tooltip）
- 麦克风被拒：「麦克风权限被拒绝 · 可在浏览器设置中重新授权」+「改用文件上传」
- 推理失败：错误卡「推理失败：XXX」+「重试」+「反馈这段音频」
- 音频质量差（P1 质量预判）：「检测到音频几乎无声/大量噪音，建议换用清音版本」+「仍要继续」
- 整体置信度 < 0.40：顶部黄色横幅「这份音频自动扒谱效果不佳」+「仅用和弦模式」「手动录入」「换一段音频」

**边界条件**
- 音频时长 > 300s：提示「建议裁剪到 5 分钟以内以获得更快更准的结果」，允许继续
- 采样率非 44.1/48k：`decodeAudioData` 后统一重采样到 16k mono
- 立体声：混合为单声道
- 用户离开页面：Worker 随页面销毁，任务标记「已中断」，回来后列表显示「已中断 · 重新扒谱」
- 不支持 Worker / OfflineAudioContext：整页降级提示「当前浏览器不支持本地推理」

### 4.4 校对编辑器 `/transcribe/:jobId/edit`

**页面要素**
1. 顶部：待确认进度条「还有 N 处需要确认」（★）+「已确认 X / N」+「跳到下一处 ▸」
2. 波形时间轴（上）：peaks 波形 + 播放头 + 低置信区段半透明黄色遮罩
3. 和弦轨：每小节一行和弦，可疑和弦带 `?` 与虚线
4. 六线谱编辑区（主）：点选/框选/拖动，琥珀虚线框 = 低置信
5. 渐进式右栏：待确认清单 / 节奏型模板库 / 选中音符属性（弦·品·时值·置信度）
6. 右上角唯一出口：「完成并入库」

**主要交互**
- 三视图（波形 / 和弦轨 / 六线谱）共享 `currentTick` 与选区，任一侧点击另两处同步
- 点音符 → 属性面板可改弦（1–6）、品（0–24）、时值；点击即试听
- 拖动音符上下 → 换弦
- 点和弦 → 候选和弦弹窗（按 chroma 距离 Top 8，带相似度 %）→ 选中后该小节音符按当前模板重生成
- 悬停低置信音符 → tooltip 列出最多 3 个候选 (弦, 品) → 点击切换，`confidence` 置 1.0，从清单移除
- 选模板 → 试听 → 「应用到全部并生成谱面」→ 六线谱重绘（一步撤销）
- 「跳到下一处 ▸」→ 定位 + 高亮 800ms
- 编辑或点「✓ 确认」→ N 递减；N=0 时进度条变绿 + 「全部确认完毕」

**空状态**
- 初稿 0 音符（仅和弦模式）：六线谱区「这份初稿只有和弦 · 从右侧挑一个节奏型生成音符」
- 无低置信项：进度条直接显示「全部确认完毕」+ 绿色
- 无 peaks（音频已清理）：波形区用 notes 密度生成替代波形 + 灰字「原始音频已清理，波形为示意」

**加载态**
- 进入编辑器：骨架 +「正在加载初稿…」
- 应用模板：按钮转圈 +「正在生成 24 小节…」，> 2s 显示进度
- 试听：按钮转圈 + 波形区播放头走动

**错误态**
- jobId 不存在：整页「找不到这个扒谱任务」+「返回扒谱页」
- 草稿损坏：弹窗「草稿读取失败」+「重新开始（丢弃草稿）」/「返回」
- 生成失败（和弦不在和弦库）：跳过该小节并在待确认清单新增「第 M 小节 · 和弦无法识别」，不中断整体生成
- 自动保存失败（IndexedDB 满）：黄色横幅「本地存储已满，草稿可能丢失 · 请尽快入库或清理旧任务」

**边界条件**
- 一小节内多个和弦：按和弦 tick 边界切段，每段独立铺一次完整 pattern（slotTicks 按比例压缩）
- pattern 长度与小节的 slot 数不符：按「pattern 长度优先」，`slotTicks = round(段ticks / pattern.length)`
- 品位数 > 24：拒绝输入并 toast「品位范围 0–24」
- 撤销栈超 50 步：丢弃最早的一步，不报错
- 入库时曲名为空：默认填「未命名扒谱 · MM-DD」，允许后续编辑
- 入库后原音频 Blob 删除；再次打开该 job 编辑器时波形为示意波形

- 本周无练习：指标卡显示 0 + 「本周还没开始练习」

**加载态**
- 日历与列表：骨架屏；聚合计算 > 500ms 时显示「正在统计…」

**错误态**
- 曲目已删除的记录：曲名置灰显示「（已删除）」，时长仍计入统计，点击不跳转
- 数据异常（会话 endedAt < startedAt）：跳过该条并在 console 警告

**边界条件**
- 跨月：日历默认显示当前月，可左右切月，无数据的月份显示「本月没有练习」
- 连续打卡：当日或昨日有练习才累加，否则归零（避免"隔天练"被算成连续）
- 单日多会话：时长累加，打卡只记一次
- 有效时长 < 300s 的会话：不计入打卡与曲目时长，但写入 `sessions` 且 `counted = false`

## 5. 数据定义

### 5.1 通用约定（写死，不得自行发挥）

| 约定 | 规则 |
|---|---|
| 时间单位 | **Tick**。`ticksPerBeat = 480`（1 四分音符 = 480 ticks）。4/4 一小节 = 1920 ticks；3/4 一小节 = 1440 ticks。所有位置/时值字段都用 tick，**禁止用秒** |
| tick → 秒 | `seconds = tick × 60 / (480 × currentBpm)` |
| 弦号 | `string: 1–6`，**1 = 高音 E（最细）**，6 = 低音 E（最粗）。与吉他通用记法一致 |
| 和弦图 `diagram` | 长度 6 的字符串，**index 0 = 6 弦，index 5 = 1 弦**（从低音弦到高音弦）。每字符为 `0-9`（品位）或 `x`（不弹）。正则 `^[xX0-9]{6}$`。例：C = `x32010` |
| ⚠️ 易错 | `note.string` 的方向（1=高音）与 `diagram` 的方向（index0=低音）**相反**，转换公式：`diagramIndex = 6 - string` |
| confidence | `∈ [0,1]`，float，保留 2 位。人工编辑后置 `1.0` |
| 主键 | `id` 用 `<前缀>_<24 位 ULID>`，如 `tab_01J8XQ7T2R4V6M8N0P2Q4S6T` |
| 时间 | 一律 ISO 8601 UTC，如 `2026-09-08T12:00:00Z` |
| 存储 | 索引/设置 → localStorage（键前缀 `fretly.`）；谱面/音频/草稿/会话 → IndexedDB（DB `fretly`，stores: `tabs` / `audios` / `drafts` / `sessions` / `jobs` / `collections`） |

### 5.5 难度自动计算（写入 `difficulty`）

```
difficulty = clamp(round(1 + 4 × D), 1, 5)

D = 0.35 × barreRatio          // 含横按和弦数 / 不同和弦总数
  + 0.25 × chordChangesDensity  // min(1, 和弦变化次数 / 小节数)
  + 0.25 × speedRatio           // clamp((bpm - 60) / 120, 0, 1)
  + 0.15 × techniqueDensity     // min(1, 带技巧音符数 / 总音符数)
```
- `barreRatio` 依据和弦库中的 `barre: true` 标记判定（F / Bm / Bb / F#m）
- 用户手动覆盖后写 `difficultyOverride`，筛选与列表以覆盖值为准，但 `difficulty` 保留系统值（覆盖值清空后可恢复）

## 6. 熟练度与 BPM 计算规则

### 6.1 熟练度 Mastery（0–100）

**四个因子与权重**

| 因子 | 权重 | 符号 | 计算式 |
|---|:--:|:--:|---|
| 速度达成率 | 40% | `S` | `S = clamp(bestBpm / targetBpm, 0, 1)`；`targetBpm` 缺省 = `tab.bpm` |
| 覆盖度 | 25% | `C` | `C = coveredMeasures.length / totalMeasures`；`totalMeasures = tracks[0].measures.length` |
| 达标率 | 25% | `A` | `roundsTotal ≥ 1 ? roundsPassed / roundsTotal : 0` |
| 新鲜度 | 10% | `F` | 见下表 |

**新鲜度 F（分段线性，下限 0.5，绝不归零）**

| 距上次练习天数 `d` | F |
|---|---|
| `lastPracticedAt == null` | `0` |
| `d ≤ 7` | `1.00` |
| `7 < d ≤ 30` | `1.00 − 0.15 × (d − 7) / 23` （1.00 → 0.85） |
| `30 < d ≤ 90` | `0.85 − 0.35 × (d − 30) / 60` （0.85 → 0.50） |
| `d > 90` | `0.50`（保底） |

> 设计意图：熟练度是**激励工具不是测量工具**。它不要求绝对准确，但绝不能断崖下跌——新鲜度下限 0.5 保证长期不练最多只掉 5 分（10% × 0.5）。

**原始分与显示值**

```
computed = round(100 × (0.40×S + 0.25×C + 0.25×A + 0.10×F))

if (practice.masteryComputedAt == null) {
    mastery = computed                      // 首次，不走平滑
} else {
    mastery = round(0.7 × computed + 0.3 × prevMastery)   // EMA 平滑，α = 0.7
}
```

**触发与边界规则（必须一起实现，否则熟练度会乱跳）**

1. **会话进行中不重算。** 仅在会话结束时（B-15 的结束条件触发）重算一次并写回 `mastery` / `masteryComputedAt`。
2. `coveredMeasures` 的写入时机：播放头**完整跨过**某小节区间，或该小节被包含在 A-B 循环区内循环一次，即把该小节 index 加入集合（去重）。
3. `roundsTotal` 每完成一轮 +1（无论达标与否）；`roundsPassed` 仅在用户点「本轮过了」时 +1。
4. `bestBpm` 仅在**连续达标达 N 轮并触发提速**时更新：`bestBpm = max(bestBpm, currentBpm)`。
5. 曲目详情提供「重算」按钮：直接 `mastery = computed`（跳过 EMA），用于用户手动覆盖参数后刷新。
6. 熟练度显示分档：<40 灰 / 40–69 蓝 / 70–89 绿 / ≥90 金。

**算例（可直接写单元测试）**

《练习曲 No.1 · 晨光》：`targetBpm = 72`，`totalMeasures = 16`。
用户练了 3 次会话，状态：`bestBpm = 58`，`coveredMeasures` = 16 个，`roundsTotal = 10`，`roundsPassed = 7`，`lastPracticedAt` = 2 天前。

```
S = 58 / 72 = 0.8056
C = 16 / 16 = 1.00
A = 7 / 10  = 0.70
F = 1.00                                   (d = 2 ≤ 7)
computed = round(100 × (0.40×0.8056 + 0.25×1.00 + 0.25×0.70 + 0.10×1.00))
         = round(100 × (0.3222 + 0.25 + 0.175 + 0.10))
         = round(84.72) = 85
若为首次重算 → mastery = 85
若 prevMastery = 70    → mastery = round(0.7×85 + 0.3×70) = round(80.5) = 81  (注：0.7×85=59.5, 0.3×70=21 → 80.5 → 81)
```

### 6.2 BPM 与速度规则

**基础**

| 量 | 规则 |
|---|---|
| 原曲 BPM | `tab.bpm` |
| 变速比 `ratio` | 0.50–1.50，步进 0.01，持久化在会话内 |
| 当前 BPM | `currentBpm = round(tab.bpm × ratio)` |
| tick → 秒 | `seconds = tick × 60 / (480 × currentBpm)` |
| 目标 BPM | `targetBpm = round(tab.bpm × targetRatio)`，`targetRatio` ∈ {0.9, 1.0, 1.1, 1.2}，默认 1.0 |

**渐进加速训练**

```
startBpm = clamp(round(targetBpm × startRatio), 40, targetBpm)   // startRatio 默认 0.60
step     ∈ {3, 5, 10}                                            // 默认 5
passRounds ∈ {1, 2, 3}                                           // 默认 2

每轮结束（播放头到达 B 点/曲尾）：
    roundsTotal += 1
    若用户在 5 秒内点「本轮过了」：
        roundsPassed += 1
        consecutive += 1
        若 consecutive >= passRounds：
            bestBpm = max(bestBpm, currentBpm)
            currentBpm = min(currentBpm + step, targetBpm)
            consecutive = 0
            若 currentBpm == targetBpm：targetReachedAt = now（首次）
    否则：
        consecutive = 0

边界：
    若 targetBpm < 40                     → startBpm = targetBpm
    若 round(targetBpm × startRatio) < 40 → startBpm = 40
    若 currentBpm 已等于 targetBpm        → 不再提速，继续循环直到用户停
```

**无缝续播的实现约束（易错）**

1. 提速**只影响尚未调度的音符**。已通过 `AudioBufferSourceNode.start(when)` 排入队列的音符不撤销（预调度窗口 `lookahead = 0.1s`，调度器 `setInterval 25ms`）。
2. Tempo 变更在**下一个小节线**生效：调度器检测到 `currentTick` 跨小节且存在 pending tempo 变更时，才用新 `currentBpm` 换算后续 tick→秒。
3. 禁止用 `AudioBufferSourceNode.playbackRate` 实现变速（会同时改变音高）。合成音轨应**按新 tick→秒 重新调度、用相同合成参数重新合成**，天然保音高。
4. 节拍器与示范音轨必须共享同一个 tempo 来源（`currentBpm`），否则会与谱面脱拍。

### 6.3 有效练习时长与打卡

```
会话开始：用户首次点击播放（AudioContext 已 resume）
会话结束：a) 暂停持续 ≥ 60s  b) 离开 /practice/:id  c) 标签页隐藏 ≥ 5 分钟
effectiveSeconds = 会话内处于「播放中」状态的累计秒数（暂停不计）

counted = effectiveSeconds >= 300
counted == true  → 写入当日打卡、practice.totalSeconds += effectiveSeconds、sessions += 1
counted == false → 仍写入 sessions 记录（counted=false），但不计打卡与时长

连续打卡天数 streak：
    从今天往前推；若今日有练习，从今日开始计数；否则若昨日有练习，从昨日开始计数；否则 streak = 0
    中途断一天 → streak = 0
```

## 7. 节奏型模板清单（12 个）

### 7.1 通用规则

- **slot（格）**：一个模板的 `pattern` 字符串按字符等分一小节。字符位置 = slot 索引（从 0 起）。
- **slotTicks 计算**：`slotTicks = round(和弦段tick数 / pattern.length)`。
  - 4/4 一小节 1 个和弦（1920 ticks）+ 8 字符 pattern → `slotTicks = 240`（八分音符）
  - 3/4 一小节 1 个和弦（1440 ticks）+ 6 字符 pattern → `slotTicks = 240`
  - 一小节 2 个和弦（各 960 ticks）+ 8 字符 pattern → `slotTicks = 120`（十六分音符）
  - **这样模板自动适配任意拍号与和弦密度，无需额外参数。**
- **字符语义**
  - 扫弦类：`D` 下扫、`U` 上扫、`x` 闷音下扫、`-` 空（不发声）
  - 分解类：`1`–`6` 拨该弦（**弦号：1 = 高音 E**）、`-` 空
- **noteDur（音符时长）**：从当前 slot 到下一个非空 slot 的 tick 差；最后一个非空 slot 延伸到和弦段末尾。

### 7.3 (弦, 方向) 生成规则 —— 工程师直接照此实现

**输入**：当前和弦事件的 `diagram`（6 字符，index0 = 6 弦）、slot 内的字符、当前 `currentBpm`、`slotTicks`、`noteDur`。

**Step 1 — 解析和弦**

```
sounded = [ s | s ∈ 1..6, diagram[6 - s] != 'x' ]      // 注意 6-s 的方向转换
loString = max(sounded)                                 // 弦号最大 = 最低音弦
hiString = min(sounded)                                 // 弦号最小 = 最高音弦
```

**Step 2 — 计算 rake（扫弦弦间延迟）**

```
rakeTicks = clamp(round(0.006 × currentBpm / 60 × 480), 1, 12)
// 例：BPM 72 → round(0.006 × 1.2 × 480) = round(3.456) = 3 ticks（≈6ms）
```

**Step 3 — 按字符生成 (弦, 方向) 序列**

| 字符 | 弦序列（按顺序发声） | `stroke` | `velocity` | `techniques` |
|---|---|:--:|:--:|---|
| `D` 下扫 | `[loString, loString-1, ..., hiString]`（弦号递减，低音弦→高音弦） | `D` | 0.85 | `[]` |
| `U` 上扫 | `sortedAsc(sounded ∩ {1,2,3})`（即 1→3 弦，只到 3 弦）；若为空则 `[hiString]` | `U` | 0.65 | `[]` |
| `x` 闷音下扫 | 同 `D` | `X` | 0.50 | `["mute"]` |
| `n`（1–6，分解） | `[n]`；若 `diagram[6-n] == 'x'` 则替换为 `[loString]` | `P` | 0.75 | `[]` |

**Step 4 — 写入 tick 与时长**

```
设序列长度 = k，slot 起始 tick = T
for i in 0..k-1:
    note.startTick    = T + i × rakeTicks
    note.durationTick = (i < k-1) ? rakeTicks
                                  : max(1, noteDur - (k-1) × rakeTicks)
    若字符为 'x'：note.durationTick = min(note.durationTick, 120)
    note.fret = diagram[6 - note.string] 解析出的整数（'x' 时为 0）
    note.confidence = 1.0     // 模板生成的音符视为确定，不进待确认清单
```

**边界保护**
- `k = 0`（和弦全为 `x`，不应出现）→ 跳过该 slot 并在 console 警告
- `noteDur - (k-1) × rakeTicks ≤ 0` → 强制 `durationTick = 1`，并把 `rakeTicks` 压缩为 `max(1, floor(noteDur / k))`
- 分解模板 `n` 对应的弦在 diagram 中为 `x` 时，替换规则见上表（例：D 和弦 `xx0232` 用 5323 → 5 弦为 `x`，替换为最低有声弦 = 4 弦）

## 9. 待确认问题

> 以下为 PM 判断需要主理人/研发确认的点，**每条已给出建议默认值**。若在 M1 开工前未收到反对意见，按建议默认值执行。

| # | 问题 | PM 建议默认值 | 影响面 |
|:--:|---|---|---|
| Q1 | 示范音轨合成算法选哪种？ | **主推 Karplus-Strong 拨弦物理建模**（白噪声激励 + 延迟线 + 低通反馈，零采样体积，天然变速不变调）。备选：精简采样表（约 200KB base64 内嵌）。若 K-S 音色试听不满意再切采样表 | B-06，M1 最大技术风险点，建议第 1 周就做音色 spike |
| Q2 | 内置示范曲是否含独立旋律轨？ | **否**。单吉他轨，音符全部由「和弦 + 节奏型模板」生成。理由：不需要额外旋律数据，且顺带自检节奏引擎 | §8、A-08 |
| Q3 | 3/4 拍是否必须支持？ | **是**。No.4 是 3/4，渲染器需按 `timeSignature[0]` 计算小节 tick（`3/4 → 1440 ticks`） | B-01、§8 |
| Q4 | MusicXML 导入的保真范围？ | 只导入 **6 弦标准调（EADGBE）的吉他轨**；忽略打击乐与非 6 弦轨；**不展开反复记号**（Da Capo / Segno 一律线性展开为实际小节，若文件含未展开的跳转则提示"反复记号已忽略"）；不支持多声部（同 tick 多音只保留品位最低的一个） | A-05 |
| Q5 | ASCII 六线谱解析的严格度？ | 宽松解析：识别 `e/B/G/D/A/E` 或 `1/2/3/4/5/6` 开头的 6 行块；允许行首带 `|`；未识别的字符按 `-` 处理并计入"部分解析"；不要求小节线对齐 | A-05 |
